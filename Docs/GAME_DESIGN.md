# 《烬潮：归炉》设计基线

> 最新美术方向：日本热血战斗动漫。保留归炉城与三角色世界设定，使用夸张姿态、清晰色块、亮芯刀光与冲击反馈；本文件早期工业写实倾向不覆盖新方向。当前实现见 `ANIME_COMBAT.md`。

## 产品支柱

1. **动作有反馈：**准确命中、清楚受击、可学习的取消与防御节奏。
2. **三人有协作：**牵制、破势、追击互相创造机会；各角色仍能单独游玩。
3. **画面有辨识度：**东方工业奇幻、黑铁与青瓷、朱砂和炉火；战斗可读性优先。

平台为 Windows；1～3 人局域网房主制。关卡线性推进，采用侧面斜视镜头和有限纵深移动。完整产品目标三角色、六关、四主要 Boss，首次流程约 3～4 小时。灰盒阶段只验证基础动作与网络闭环，不代表完整体验。

## 世界与剧情

归炉城以巨大炉心把人的记忆转化为能源。最初人们自愿献出痛苦，后来城市开始强制收取。一次失控让被剥离的记忆化成“烬”，寄生于机械和人体。城市封闭，炉心却依然运转。

三位主角分别参与过同一场灾难的押送、制造与善后。入城时，他们以为熄灭炉心即可解决灾难；随后发现幸存者也依靠炉心生存。最终击败守炉者，为城市建立新的循环。首发采用固定主线结局，通过环境、短对话与战斗演出叙事，避免多分支演出膨胀。

主题：失去记忆不能免除责任。

## 人物与战斗职能

| 人物 | 身份与动机 | 武器、轮廓与配色 | 机制方向 |
|---|---|---|---|
| 沈砚 | 前守城军人，寻找失踪妹妹并面对押送责任 | 长刀、宽肩、短披风、深红 | 正面牵制、防反、高架势伤害 |
| 阿绫 | 机关师，追查自己设计的装置为何失控 | 双短刃、机关臂、轻装、青绿 | 机动、牵引、空中追击 |
| 闻灯 | 引魂人，能听到怪物残留的人声 | 长柄灯杖、宽袖、灯环、暖金 | 聚怪、标记、控制与支援 |

沈砚技能方向：截火防反、压山重斩、回炉突进、断城大招。阿绫：飞梭牵引、燕返空战、裂步爆破、百械连击。闻灯：引灯聚怪、照影打断、渡火转化、长夜明领域。以上是后续完整角色目标，灰盒不要求一次全部实现。

## 操作与战斗规则

移动、轻攻击、重攻击、跳跃、闪避、两个技能、特殊技和交互。基础连段采用轻击主干加重击分支；方向重击挑空，空中重击砸落。普通轻击不消耗气力，防御与强技能需要资源管理。

角色拥有生命、气力和共鸣；敌人拥有生命与架势。重击、防反与特定技能削减架势，破势制造输出窗口。Boss 使用独立恢复和控制抗性，禁止无限浮空和永久硬直。默认关闭同队伤害。

共鸣通过进攻、救援与联动积累：一人破势或挑空，另一人追击产生强化反馈。演出在原镜头内完成。倒地后可被持续交互救援；全队倒地回检查点。当前已按新增需求提供测试用 AI 补位；复杂导航与正式队友剧情仍待开发。

命中系统使用连续体积扫掠、攻击实例去重、服务器权威伤害和受限目标辅助。攻击的预备、有效、随动、恢复和取消阶段数据化。局部动画顿帧、镜头与音效反馈不得暂停全局服务器时间。

## 关卡与敌人

| 关卡 | 主视觉 | 核心变化 | 高潮 |
|---|---|---|---|
| 灰渡码头 | 灰水、货吊、封锁线 | 轻重击、纵深、破势与救援教学 | 缆索监工精英 |
| 百炉工坊 | 锻锤、黑铁、炉火 | 传送带与过热场地 | 铸炉官 |
| 雨巷旧城 | 雨、青瓷、残破居所 | 屋顶、窄巷、远程威胁 | 无面巡使 |
| 悬灯水道 | 水网、灯阵、记忆残影 | 移动平台、区域控制 | 精英组合战 |
| 断桥天轨 | 高架、断桥、车厢 | 移动战场、分层空间 | 负山运输机 |
| 归炉心室 | 炉心、巨构、明暗对比 | 全机制综合 | 守炉者 |

目标单关 25～35 分钟，检查点约隔 5～8 分钟。合作机关允许多人加速，同时保留单人解法。首个垂直切片选择工坊，先验证完整关卡生产流程。

基础敌人：灰民（近战）、盾役（正面防御）、炉枪兵（直线威胁）、吊索手（牵引）、烬犬（突进）、灯蛾（空中骚扰）。精英需改变招式而非单纯增加生命。AI 使用进攻名额限制同时高威胁攻击，不能让三人战斗失去反应空间。

铸炉官三阶段：重锤与炉火；传送带和冷却阀；护甲脱落后的快节奏连击。每阶段必须有可读前摇、应对策略和奖励窗口，机制可以被单人顺序完成。

## 美术、镜头与声音

场景按前景、主战斗区、中景机械、远景城市分层。前景遮挡玩家时淡出。角色依靠轮廓与动作区分；敌方预警同时使用形状、动态边界与颜色，不能只靠色相。

侧面斜视透视镜头保留空间感。正式版本按队伍包围盒平滑取景，限制极端落单；灰盒可采用固定镜头。提供震动、闪光和动态模糊选项。

动画重点分别是沈砚的重量与随动、阿绫的弧线和轻快节奏、闻灯的圆形范围控制。轻微受击、强受击、击退、挑空、倒地、破势和护甲抵挡应使用不同反馈。

重击声音组合挥动、材质接触、低频冲击、敌人反馈和破势提示。音效并发需排序，Boss 预警和危险信息优先。三人混战时减少持续遮挡与过曝。

## 技术与制作基线

UE5，C++ 核心逻辑、数据资产与蓝图内容。X 为横向推进，Y 为有限纵深，Z 为跳跃。房主同时为权威服务器；移动使用引擎复制，AI、伤害、奖励与阶段在服务端决定。

先用灰盒验证输入、命中、联机与关卡节奏，再制作正式资产。角色资产流程为概念、轮廓、模型、绑定、动作、材质和三人同屏验证；关卡为灰盒、遭遇验证、模块套件、灯光和优化。

性能以指定 Windows 硬件上的三人复杂战斗为依据，目标稳定 60 FPS。引擎版本、插件版本、资产许可证与二进制资源协作规范需要固定并记录。当前云环境的静态检查不能替代 Windows 编译、打包和局域网验证。

## 当前灰盒实现与完整设计的差异

实现进度以 `M1_PROGRESS.md` 为准。当前代码包含三角色固定属性和各三项 U/I/O 技能、救援、个人共鸣及合作命中奖励。它们是机制验证：沈砚使用短时防护冲击代替完整时机防反，阿绫使用位移与挑空范围技能，闻灯使用聚怪和范围架势伤害。当前实现已改为严格 U/I/O 能量与独立终极，旧的满共鸣自动强化不再适用。

铸炉官当前是两阶段、三类范围招式的灰盒，第三阶段、传送带和冷却阀仍待制作。命中窗口采用前摇结束时的一次扫掠，尚未实现动画驱动的连续武器轨迹。房间使用直接 IP，自动发现尚未实现。当前静态镜头与基础形体用于开发验证，不代表最终画面质量。Boss 预警采用实例静态网格边界，代码不依赖调试绘制开关；仍需 Shipping 打包验证。技能反馈仍使用调试绘制，发布前需替换为正式可见资产。

代码式 UMG 房间面板已包含创建、直接 IP 加入、选角、显式开局、重开和 Tab 开关，保留控制台备用入口。战斗与间歇中拒绝加入，开局人数锁定本轮缩放，掉线后需等待准备或结果阶段。以上界面和连接行为均未在引擎运行验收。

这些源码仍缺 UE 编译、渲染、物理与 Windows 联机验证。M0 的运行门槛必须先通过，不能因 M1 功能数量增加而跳过。

当前键位、五段连招、奔跑/翻滚/跳跃及能量获取成本以最新 `PLAYER_CONTROLS.md` 为准；本文件旧的气力与共鸣构想属于早期设计，不应覆盖当前用户规则。
