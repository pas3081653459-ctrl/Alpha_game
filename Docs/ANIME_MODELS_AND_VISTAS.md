# 动漫人物、立体关卡与远景

## 设计资产

`SourceArt/Characters/References/AnimeHeroTurnarounds.png` 为本轮原创生成的三名英雄正面、侧面、背面设定：赤衣刀客、青白拳师、金白灯术师。三视图是造型参考，不是把平面人物贴到角色身上。`References/manifest.json` 记录图源与 SHA-256。

`Scripts/generate_character_meshes.py` 使用 Blender 制作三套分部静态网格，21 个 FBX 存在 `SourceArt/Characters/`，沿用身体与四肢 pivot 的程序动画。脸部、眼睛、发型、前襟、衣摆、手套与鞋靴由网格表达，使用语义材质槽保留皮肤、衣物和深色线条。当前不是手工高精度雕刻、骨骼蒙皮或动作捕捉，敌人/Boss仍使用已有造型。角色武器、打击特效和动作时序沿用现有系统。

`SourceArt/Backdrops/T_ChapterPanoramas.png` 是原创生成的1254×1254三行画幅：上为黎明港湾，中为熔炉山谷，下为夕阳水城。各章材质只采样对应一行；采用 Unlit 双面材质，保持画面亮度，不参与碰撞和阴影。背景板按当前章节与视口尺寸定位，平面正对战斗镜头。图片提供场景外风景，近景仍为真实3D几何；宽画幅在近距离可能需要更高分辨率迭代，不能代替可探索场景。

## 实际地形

三章高度分别最高120、220、180cm，连续坡道连接高台，地面可视网格和碰撞共享同一高度剖面。起点与NPC区保持平坦；路线箭头、刷怪点、Boss与地面预警跟随地面。详见 `TERRAIN_UPGRADE.md`。没有依靠装饰物假装成可行走高台，也未加入AI必须跳跃的断路。

## 导入与构建

先 `git lfs pull` 取得FBX源。Mac：

```bash
./Scripts/Build-Mac.sh "/Users/Shared/Epic Games/UE_5.6"
```

Windows 使用现有 `Scripts/Build-Windows.ps1`。两端在编译后运行 `create_visual_assets.py`：导入21个角色部件和远景材质到 `/Game/Art`，保存当前调用的 `Artifacts/Visuals` 报告并验证资源包存在。普通Editor启动也会按源指纹生成，已有相同指纹则跳过；失败时Python日志明确报错。非本生成器所有的同名资源不会被覆盖。需要保留手改资源请先复制为别的名字。

角色资源缺失时回退原型并警告；远景资源缺失则不显示背景板。只有代码拉取、没有执行导入时，不能期待新模型已出现在游戏里。生成的uasset由本机UE保存，源FBX/PNG随仓库分发。无需用户本机安装Blender即可导入；只有重新建模才需要Blender。

## 验证边界与验收

云端已执行八套可移植测试及各自UBSan：战斗222、表现320、同伴784、控制1174、剧情510、地形8106、敌人375、存档182，共11673项。工程检查通过，发现46项UE测试源码，未执行UE编译或渲染。Blender离线预览只用于检查导出模型比例、面部和拼装，不代表UE游戏截图。

Mac/Windows需实际验证：

1. 完成构建和资源生成，确认没有Python、FBX材质槽或shader错误；分别选三名角色，检查朝向、脸和材质颜色，以及跳跃、五连击、翻滚、技能的部件拼接。
2. 三章从NPC走到终点，验证连续坡道无卡顿、出生点未陷地、队友与敌人能爬坡，Boss预警不埋地。
3. 单人、三人拉远镜头，16:9与宽屏窗口下检查背景不露板边、不颠倒、不串章；标题菜单/章节重玩后背景同步。
4. 运行46项UE自动化，并做打包渲染和真实LAN验证。离线计算通过不替代这些门槛。
