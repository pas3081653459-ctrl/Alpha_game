# M0 / M1 验收与测试记录规范

## 状态约定

本文件是测试计划，**不表示测试已执行或通过**。源码评审、脚本检查、UE 编译、编辑器运行、Windows 打包和三台设备联机分别记录。当前云环境没有 Unreal Editor，UE 相关结果默认“未执行”。

每条记录至少包含：日期、提交 SHA 或工作树快照标识、UE 版本、构建配置、设备与系统、操作步骤、预期、实际结果、日志路径、通过/失败/阻塞/未执行。缺少运行环境标为阻塞；未实现功能标为未执行并关联后续任务，不能当作通过。

## 1. Windows 构建与启动

准备安装项目锁定的 UE5 版本、匹配的 Visual Studio C++ 工具链与 Windows SDK。正式版本锁定前，以工程说明为准记录实际版本，不能自行宣称跨版本兼容。

1. 在干净目录取得仓库；拉取使用 Git LFS 的二进制资源（如已加入）。
2. 生成项目文件，构建 `AlphaGameEditor` 的 `Win64 Development` 目标。
3. 打开工程，确认没有缺失模块、类、插件或默认地图错误。
4. 按 README 的默认入口运行，确认场景、角色、HUD 与敌人出现。
5. 生成 Windows Development 包，在未安装编辑器的目标电脑启动。
6. 记录实际加载的地图、GameMode、Pawn、PlayerController 与 HUD，排查配置仅在编辑器生效的问题。

通过条件：真实编译结束码为 0、编辑器运行无阻断错误、打包程序能进入战斗。三项独立记录。

## 2. 单机基础闭环

| ID | 操作 | 预期 |
|---|---|---|
| LOCAL-01 | 四向移动、跳跃、连续改变方向 | 角色不穿地，不离开设计战场；攻击方向可理解 |
| LOCAL-02 | 连按轻重攻击 | 冷却生效，不能每帧无上限结算 |
| LOCAL-03 | 贴近与远离敌人攻击 | 有效范围内命中，范围外不扣血 |
| LOCAL-04 | 同一攻击覆盖多个敌人 | 每个目标按设计结算一次，不随帧率重复伤害 |
| LOCAL-05 | 持续闪避 | 冷却与移动限制生效，不可无限加速 |
| LOCAL-06 | 玩家生命耗尽 | 进入死亡状态，停止攻击与正常移动；HUD 一致 |
| LOCAL-07 | 消灭一波敌人 | 剩余数量正确，下一波按设计出现，无空波卡死 |
| LOCAL-08 | 完成最后一波 | 明确胜利状态，不继续无限生成敌人 |
| LOCAL-09 | 失败后重开 | 玩家生命和运动恢复；旧敌人与计时器不污染新轮次 |

若灰盒闪避仅为位移，不含无敌帧，记录为已知范围，不宣称已实现完整闪避设计。救援、动画取消、破势受击和三角色技能未进入本轮时同样注明。

## 3. 三台真实 Windows 设备局域网

三台设备使用同一构建版本并处于可互通局域网。记录有线/无线、IPv4、网卡类型、实际连接端口与 Windows 防火墙规则。不要把同一电脑的三个窗口作为真实局域网验收。

1. A 创建房主游戏；B、C 通过项目提供的直接 IP 入口加入。
2. 三人分别移动、跳跃、攻击、闪避；各端观察位置与状态。
3. 三人同时攻击同一敌人，核对敌人生命、死亡和剩余数量。
4. 三人分散并分别吸引敌人，确认 AI 由服务器决定目标。
5. 让一名玩家死亡，确认其余客户端看到一致状态；敌人不持续追逐死亡对象。
6. 完成波次并重开，检查所有客户端同步恢复。
7. 第四个客户端尝试加入，必须被明确拒绝，不能生成第四名角色。
8. 一名客户端退出，再尝试加入；战斗/间歇中应被拒绝且不改变本轮缩放，准备/结果阶段可重新加入；验证席位释放。
9. 房主退出，其他客户端获得可理解的失败信息或返回流程；首发不要求房主迁移。
10. 输入不存在的地址、非法字符或控制台分隔符，确认输入被拒绝或安全失败，不能执行额外命令。

若只有直接 IP 已实现，自动发现测试保持未执行。若断线仅依赖引擎默认处理，记录实际表现，不能宣称正式错误界面完成。

## 4. 权威性与网络恶劣条件

先在引擎支持的网络模拟环境验证，再补充真实设备观察。记录采用的模拟方式与参数，不预设某个 UE 版本的命令始终可用。

| ID | 条件与操作 | 预期 |
|---|---|---|
| NET-01 | 客户端高频发送攻击请求 | 服务端冷却限制生效，无额外伤害 |
| NET-02 | 多客户端同步攻击 | 每次合法命中结算一次；各端生命最终一致 |
| NET-03 | 客户端改变本地生命显示 | 权威状态不受影响；不能据本地状态决定死亡 |
| NET-04 | 约 50、100、150 毫秒延迟分别测试 | 不产生永久状态卡死、无限攻击或重复击杀；记录操作感差异 |
| NET-05 | 约 1%、3% 丢包分别测试 | 关键状态最终收敛，波次不因丢失表现事件停滞 |
| NET-06 | 攻击中死亡、断线、重开 | 旧攻击与计时器不在新轮次产生幽灵伤害 |
| NET-07 | 多次连接退出 | 三人上限与敌人数不漂移；无无限累积对象 |

Listen Server 房主可控制服务器，这是当前信任模型；本阶段不宣称具备竞技级反作弊。不要以关闭校验、无限客户端权限来掩盖延迟问题。

## 5. 后续 M1 及视听验收

- 救援：中断、双人同时救援、救援者死亡、全灭与检查点重置。
- 人数缩放：单人、双人、三人都能完成代表性遭遇；机制不强制三人在线。
- 动作：输入缓冲、取消窗口、挑空上限、Boss 控制抗性与命中一致性。
- 顿帧：只影响相关本地表现，服务器逻辑与其他玩家不被全局暂停。
- 镜头：三人分散、空中追击、边界、遮挡与 Boss 阶段切换仍可读。
- 音画：Boss 预警优先、不过曝、同屏攻击仍能辨认敌方危险区域。
- 性能：指定硬件、分辨率和画质；记录复杂战斗帧时间、峰值对象和资源占用，不能只报告空场平均 FPS。

## 当前限制

正式角色资产、动作动画、声音、完整六关内容和三人真实 Windows 联机不能从灰盒源码本身推断完成。发布前必须补齐 Windows 编译、打包、独立设备连接与回归证据。验收中发现失败需区分代码缺陷、配置错误、网络/防火墙问题与尚未实现范围，分别建立任务。

## M1 源码推进后的增量验收

当前仍需先通过前述 M0 编译和单机闭环。补充验收按实际代码入口执行，不以文档描述代替运行。

| ID | 操作 | 预期 |
|---|---|---|
| M1-UI-01 | 打开房间面板，输入 IP、创建、加入、选择角色；Tab 开关 | 面板与鼠标输入切换正确，不误触攻击；控制台入口仍可备用 |
| M1-RUN-01 | 停留准备阶段，再由房主开局 | 准备阶段不自动刷怪；客户端不能越权开局 |
| M1-HERO-01 | 准备阶段切换三职业，战斗中再尝试 | 正确应用属性与外观；战斗中不能通过切角回血或重置技能 |
| M1-SKILL-01 | 各职业使用 U/I/O 三技能，连按并模拟延迟 | 服务端冷却、命中和资源一致，不能穿墙伤害或多次消费同一技能 |
| M1-COOP-01 | 不同玩家依次攻击同一目标，再高频交替 | 合作窗口和目标冷却正确，不因 RPC 频率无限获奖；单人不触发合作奖励 |

| M1-REVIVE-02 | 完成救援、连续倒地、全队倒地、重开 | 恢复设计比例生命和保护时间，救援时长递增到上限；全灭失败；重开清理旧状态 |
| M1-BOSS-01 | 完成三波敌人及 Boss 入场 | 按间隔进入 Boss，人数缩放以开局人数为基准 |

| M1-BOSS-03 | 打至半血、持续三人高频攻击、破势、击杀 | 切换第二阶段；不能无限硬直锁住；破势中断与胜利正确 |
| M1-RESET-01 | 波次中、Boss 中、失败和胜利后重开 | 敌人、Boss、计时器、救援占用和资源清理；回准备阶段等待显式开局 |
| M1-JOIN-01 | 战斗与间歇中尝试加入，再在准备或结果阶段加入 | 活跃关卡拒绝热加入；本轮人数缩放不改变；重新加入不能恢复战斗内旧角色状态 |
| M1-UI-02 | 菜单输入 IP、点击按钮时按攻击/技能/跳跃/移动 | 菜单交互不触发战斗动作；关闭后输入恢复；开局时按设计自动收起 |

所有上述测试当前默认 **未执行**，需要 Windows UE 与真实设备证据。Boss 预警已改为实例静态网格，需分别验收 Development 与 Shipping 包中边界形状、进度、颜色、清理及同步；不能仅从代码路径推断打包可见。技能反馈仍依赖调试绘制，当前原型优先使用 Development 包；Shipping 正式发布前需补正式技能特效。纯 C++ 规则测试通过只证明共享数学与条件边界，不证明 UHT、网络 RPC、复制、碰撞和 UI 可用。

新键位、五段/空中连招、双击奔跑和严格能量成本验收以 `PLAYER_CONTROLS.md` 的 CTRL-01～CTRL-16 为准。
