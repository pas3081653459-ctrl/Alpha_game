# 工坊视觉实现审查记录

## 审查范围与状态

本文件记录本轮程序化视觉代码审查与纯规则测试，不是实机画面评测。当前云环境没有 Unreal Editor，未执行 UHT/UBT 编译、UE Python 材质生成、渲染、cook 或 Windows 性能采样。没有把概念图或离线示意当作实机截图。

本轮进行了环境、角色组件、网格效果、镜头和材质管线的独立源码审查；部分集成由主智能体最终核查。新代码存在不能视为画面通过。

## 必须检查的集成边界

| 领域 | 代码检查要求 | 仍需引擎验证 |
|---|---|---|
| 碰撞 | 装饰、角色构件、招式视觉无碰撞与导航影响；保留原有战斗胶囊与地板 | 三人移动、跳跃、近墙攻击与 Boss 范围 |
| cook | 基础形体有硬引用或显式 cook 保证；生成材质被保存且纳入打包 | 清洁 checkout 生成后 cook，在无编辑器电脑加载 |
| 材质参数 | 参数名与图接线匹配；颜色/金属/粗糙/发光/透明各有正确通道 | 实际材质编译、曝光与 Bloom 变化 |
| 生命周期 | 临时效果到期销毁/回收；重开和断线不积累对象；没有纯装饰服务端重复生成 | 连续战斗与多轮重开后的对象、组件、内存 |
| 网络 | 视觉不驱动伤害；权威事件触发一次；客户端局部效果不重复复制 | 房主与两客户端同时观测 |
| 帧成本 | 重复几何批量化，限制组件/Actor/材质槽和阴影；避免每帧清空重建固定网格 | 实际 draw calls、GPU、Game/Render Thread 帧时间 |
| 可读性 | 形体、轮廓、预警与技能范围可区分；不依赖单一色差或 Bloom | 三人同屏和低画质录像 |

## 当前结果

### 纯 C++ 行为测试

`python3 Scripts/run_presentation_tests.py` 实际执行结果：**270 / 270 条检查通过**。使用 `g++ -std=c++17 -Wall -Wextra -Werror -pedantic` 编译，产物在临时目录，编译或执行失败保留返回码。另用 `-fsanitize=undefined -fno-sanitize-recover=undefined` 编译同一测试，270 / 270 通过，无 UBSan 报告。

测试直接调用 `Rules/PresentationRules.h`，覆盖：

- `CameraDistance`：常见宽高比、超宽、队伍分散单调性、距离上下限、负值、极端有限值、NaN 与正负无穷。
- `BlendWeight`：精确指数权重、0/负时间与速度、长帧钳制、无穷值拒绝；相同一秒内 30 FPS 与 60 FPS 的结果一致。
- `EffectEnvelope`：初始/中间/末尾、超期、负年龄、非法时长、微小时长与极端年龄；有限、非负且单调衰减。

已确认 `AlphaCombatCamera.cpp` 实际调用镜头距离和帧率无关混合，`AlphaCombatEffect.cpp` 实际调用效果包络；镜头冲击衰减也调用同一包络。测试没有复制一份独立实现。以上只证明计算行为，不证明镜头构图、材质、渲染或性能。

### 发现与修复追踪

1. **重击光弧超出伤害范围：**最初效果局部前端 305 cm，超普通近战 240 cm。效果作者已把局部前端改至 235 cm。独立复审又发现角色调用额外前移 70 cm；现已确认角色入口去掉偏移，普通攻击从角色位置生成，Boss 不生成无关的泛用刀弧。代码范围误导已修，仍需实机命中对照。
2. **生成材质 cook 风险：**运行时 `LoadObject` 字符串不是 cook 保证。已补 `DirectoriesToAlwaysCook`；打包仍需生成资源和实机加载证据。
3. **Fallback 参数能力有限：**引擎基础材质不因设置 `Glow` 自动发光。已要求文档明确 fallback 限制；完整材质需要先执行编辑器生成步骤。
4. **透明度误用：**当前效果采用实体网格缩小与亮度衰减，不声称靠 BaseColor Alpha 自动透明。未来需要透明时必须配置材质混合模式与 Opacity。
5. **被打断后仍生成刀弧：**战斗组件会取消服务端攻击计时，但视觉组件原先仍保留攻击起始时间，可能在受击中断后生成没有伤害的攻击刀弧。已核查受击与破势入口会清除待播攻击刀弧；成功闪避、技能与救援取消挂起普攻时，现已通过战斗组件的权威取消广播通知角色清理视觉攻击；销毁阶段抑制额外广播。代码链路已接通，RPC 运行表现仍需引擎验证。

6. **多人镜头下动画过度降频：**角色视觉最初以距镜头 2800 cm 为 15 Hz 门槛，而新镜头在正常多人构图中会拉至约 3300～3800 cm。这样可能把主要屏内角色统一降频。现已把降频阈值提高至 4500 cm，保持正常最远镜头下主要角色每帧更新；超过 6000 cm 才关闭视觉 Tick，并以低频计时器唤醒。代码修复已核查，实际动画流畅度仍需运行验证。
