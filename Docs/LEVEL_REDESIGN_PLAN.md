# 三章关卡重设计：先规划，后编码

## 本次规划的边界与参考

本文件是本轮地图编码前的设计输入，不是已完成地图或实机验收记录。参考以下同类作品的通用关卡组织方式：

- 《街头怒之铁拳4》：短连接段与清晰遭遇空间交替；敌人出场位置、场景地标和战斗边界一起变化。
- 《龙之皇冠》：前景、主战斗层、中景与远景分工；用可读地标提示路线与支路，不用大面积装饰遮住玩家。
- 《忍者神龟：施莱德的复仇》：在连续推进中切换窄宽、纵深、入口方向和场景事件，而不是让每一波都在同一空地出现。

这些是基于既有知识提炼的设计原则，本轮没有联网检索或声称复现其具体地图；不复制任何现成地图、美术、角色或贴图。

核心修改：从三块相同的矩形战斗台，改成三个轮廓、连接段和遭遇节奏不同的可行走区域。不能只把原平台换颜色，也不能在新装饰下面继续保留整张矩形隐藏地板，让所有缺口实际上仍可通行。

## 当前工程约束与必须同步修改的部分

三个地区原点保持 `(0,0,0)`、`(6000,0,0)`、`(12000,0,0)`。下述全部坐标为相对地区原点的厘米坐标。每章总体X范围 `[-1400,2500]`，相邻章仍有2100cm以上间隔；不需要UE关卡流送即可独立摆放。

当前AI只会直线跟随和短距离避险，没有NavMesh。第一批必须保证主路连续、不需跳跃、不使用移动平台、不放不可绕过的箱墙，也不把敌人生成在不能靠近的装饰台上。复杂台阶、移动桥、落水伤害和正式垂直分层不属于首批承诺。

实现前必须把以下硬编码改为共用布局数据：

1. `GameState::BuildPrototypeArena` 的单块28×8地板和四条整场围墙。
2. `GameMode` 固定在 `(650/830,Y,110)` 的所有波次出生点，以及工坊Boss的 `(800,0,150)`。
3. `CombatCamera` 固定中心X±350和地区筛选±1700。新地图需跟随整条路线，并覆盖最大可行走Y与跳跃高度。
4. `Companion::MoveToward/ChooseEvadeDestination` 固定X±1250、Y±300的矩形钳制。新AI必须把目标投影到当前路线，并在跨窄连接段时使用中心航点。
5. 美术地板与碰撞地板必须由相同数据生成，否则会出现可见桥外落脚、看似缺口可通行、地板悬空等错位。

## 统一功能分区

每章都有入口/NPC准备区、第一遭遇区、连接段、第二遭遇区和出口地标。NPC仍固定在 `(-1000,0,0)`，避免剧情验证与现有F交互失配；准备出生点建议为 `(-650,-100,110)`，玩家向左走近NPC。入口区不是额外无敌区，只在战斗前没有敌人。

每个可走矩形都定义 `(MinX,MaxX,MinY,MaxY,SurfaceZ)`，地板碰撞厚100、中心Z为 `SurfaceZ-50`。相邻矩形至少重叠50cm，避免浮点缝隙。第一批所有主路SurfaceZ=0，实体挡边高度至少220cm；挡边按实际路线外轮廓生成，不在共享连接口横放整条墙。

外围挡边应与低矮栏杆/货物边沿等可见提示对齐。没有明确落水/坠落恢复前，不能做“看似可以踩过去却必死”的装饰缺口。主干最窄净深360cm，三名胶囊角色可以错身；窄桥阶段不塞满近战敌人。

## 第一章：灰渡码头——货场、窄栈桥与泊船台

| 分区 | 可行走矩形X | 可行走矩形Y | 主视觉与用途 |
|---|---:|---:|---|
| 入口棚/渡伯 | -1400～-500 | -360～360 | 停船票亭、斜挂船帆、暖色纸灯，提供任务与短距离试招空间 |
| 遭遇A：卸货场 | -550～650 | -520～520 | 宽阔纵深；货吊、垛箱在边沿；第一波先练侧向移动和救援 |
| 连接：窄栈桥 | 600～1150 | -180～180 | 连续木板、前后水面、吊绳地标；窄宽变化真实作用于碰撞 |
| 遭遇B：泊船台 | 1100～2400 | -420～420 | 船头与朱红帆形成终点轮廓；第二波从右侧与后侧分批进入 |
| 出口踏台 | 2350～2500 | -250～250 | 亮色浮标和向工坊的远景轨道，仅在通关后提示转场 |

第一波锚点 `(50,0,0)`，合法敌人出生点示例 `(350,-250,110)`、`(500,250,110)`、`(-200,250,110)`；必须与真人胶囊至少间隔250cm，检查地板与碰撞。

第二波锚点 `(1750,0,0)`，出生点示例 `(2100,-220,110)`、`(2250,220,110)`、`(1450,240,110)`。窄桥不生成敌人，不让三名玩家刚进入连接口就被两侧包围。

路线中心航点：`(-650,0)` → `(50,0)` → `(650,0)` → `(1100,0)` → `(1750,0)` → `(2400,0)`。船与水位于路线外，不能仅把桥栏杆复制成整场边框。

本轮低台：卸货场后侧 `(X=-50～450,Y=250～520)` 增加30cm高装卸台；边缘可直接step-up，并在其左侧 `(X=-230～-50,Y=250～520)` 提供长度180cm的缓坡（约9.5°）。不在平台下挖洞，主路仍连续。碰撞/可见表面同步生成；若当前布局接口只支持矩形，则先使用30cm低台与直接跨步，缓坡列下一批。80cm以上高台、强制跳跃或多层目标暂缓，不能称为完整垂直战斗。

## 第二章：百炉工坊——宽厅、侧廊与Boss炉台

| 分区 | 可行走矩形X | 可行走矩形Y | 主视觉与用途 |
|---|---:|---:|---|
| 入口/穗的记录桌 | -1400～-500 | -340～340 | 账册、暖灯与低货架；亮色纸面作为视线落点 |
| 遭遇A：锻造厅 | -550～650 | -580～580 | 本章最宽纵深，锤架和熔炉位于后景；前两波改变入口侧 |
| 连接：侧装卸廊 | 600～1200 | -280～120 | 主通路在Y=-80，视觉上偏向前侧，形成与码头中央窄桥不同的转折 |
| 遭遇B：铸炉圆厅 | 1150～2450 | -560～560 | 主炉居中远景，地面用八边形/径向拼块区分；第三波后进入Boss |
| 出口记录台 | 2400～2500 | -250～250 | 账册箱、蓝色出水管与水道远景，连接下一章叙事 |

波1/波2锚点分别 `(0,-160,0)` 与 `(300,180,0)`，允许同一大锻造厅内不同侧向遭遇，但不可把三波都留在最初原点。波3锚点 `(1750,0,0)`。Boss出生 `(1950,0,150)`，需确认其最大直线招式与玩家撤退空间；宽厅与圆厅之间的连接阶段不释放Boss攻击。

中心航点：`(-650,0)` → `(0,0)` → `(600,-80)` → `(1150,-80)` → `(1750,0)` → `(2400,0)`。从锻造厅后侧直接追向Boss时，AI必须先回连接口，不可斜切外轮廓。

圆厅的视觉可做八边形，首批碰撞可用重叠矩形得到近似宽厅，不能使用复杂凹网格要求当前AI自动绕行。传送带、过热地面、冷却阀是后续机制，不通过装饰假装已经实现。

## 第三章：悬灯水道——桥头、窄桥与双侧灯庭

| 分区 | 可行走矩形X | 可行走矩形Y | 主视觉与用途 |
|---|---:|---:|---|
| 入口/澄的守灯亭 | -1400～-500 | -360～360 | 亭子与灯册，不再沿全长重复三组拱门 |
| 遭遇A：桥头石庭 | -550～650 | -400～400 | 短促方形遭遇；边沿坐凳、低石灯，第一波强调近身互救 |
| 连接：中央石桥 | 600～1250 | -200～200 | 桥孔、下层水面、前低栏杆；保留清楚的脚底与安全边界 |
| 遭遇B：主灯庭 | 1200～2400 | -300～300 | 中央道路延伸至出口，第二波从两侧灯庭入口出现 |
| 可走前侧灯庭 | 1350～2050 | -650～-250 | 真正可走侧区，侧向绕位/救援空间，非只画在远景 |
| 可走后侧灯庭 | 1600～2250 | 250～650 | 非对称尺度，形成展开的十字/偏T形轮廓 |
| 出口灯门 | 2350～2500 | -230～230 | 唯一大灯门与聚焦金色纹章，作为本次路线的终点 |

第二波锚点 `(1800,0,0)`，侧庭出生点 `(1600,-450,110)`、`(1900,450,110)`，仅在投影/路由支持启用后使用；否则第一批只在主灯庭生成，侧庭仍允许真人步入。

中心航点 `(-650,0)` → `(0,0)` → `(650,0)` → `(1200,0)` → `(1800,0)` → `(2400,0)`；侧庭与主路各有一个Y=±250接口航点。前侧装饰高度控制在50cm以下，不能用高栏杆遮住角色或敌方预警。

不增加虚构已完成的最终Boss，第二波结束后让澄收束“停止抽取但不能抛弃城民”的本次主线。灯阵解谜、护送居民、开闸水流仍列后续。

## 权威遭遇推进与镜头

建议共享只读布局规则提供以下概念接口；最终C++命名由集成统一：

- `GetWalkableRects(Chapter)`、`ProjectToWalkable(Chapter,XY,Margin)`：服务端出生、AI目标和地板生成共用数据。
- `GetEncounterAnchor(Chapter,Wave)`、`GetEnemySpawnPoints(Chapter,Wave)`、`GetBossSpawn(Chapter)`。
- `GetRouteWaypoints(Chapter)`、`NextRouteWaypoint(Current,Destination)`：跨连接段或侧庭时先走公共接口，不能只把目标夹进整场最大矩形。
- 复制 `EncounterIndex` 或 `ActiveRouteSegment`，HUD提示“向码头/炉台/灯庭前进”；它不接受客户端提交任意坐标。

本轮MVP使用两个遭遇锚点，不做强制关闭的推进门。可保留已有波次计时，但新波次不能在所有真人还停在上个遭遇区时远端自动开打。最小实现可在Intermission给出明确前进提示后，确认全队存活且处于同一可走区域再短转场到下一锚点；有倒地队友则等待救援，不能遗弃。更完整的“真人抵达下一入口、队友跟上后开战”的空间触发列后续，AI不代替真人触发，不改变开局人数。

若本轮无法实现空间触发，允许采用明确提示的“整队短转场”到下一遭遇区，但必须写入交付限制，不得声称完整沿路探索。不能直接把一波敌人放到镜头外1500cm后照旧计时开打。

摄像机中心X随队伍走到 `[-800,2100]`，不再固定原点±350；Y取队伍包围盒中心并限制约±180，预留最大侧庭Y±650与跳跃空间。取景先排除其他地区角色，再对当前章真人/AI与当前Boss计算包围盒。对宽侧庭应增加距离而非裁掉纵深；队伍落单时有提示，不因远处装饰/未激活敌人无限拉远。

故事NPC仍在入口，战后回程路线应保持畅通。首批不做战斗结束后锁死后门的推进门。后续若增加关闭战斗门，需要检查真人、AI、倒地队友均位于门内再关闭，并提供重开恢复。

## 美术分层与贴图需求

每章只保留2～3个大地标：码头“货吊+朱帆”，工坊“锻锤+主炉”，水道“守灯亭+唯一大拱+终点灯门”。不要沿整个场地以相同步长复制同样拱门/箱子。

原创动漫贴图建议拆分为：明亮木甲板、青瓷石砖、暖色锻造金属、角色衣料/护甲色块。贴图只提供表面信息，阴影和光照仍由材质处理，避免在纹理里烘焙一大片黑影导致换光后仍黑。地板大色块+少量边沿磨损，角色用大面色、缝线与衣纹；不把满幅绘画直接铺成全身杂纹。

贴图生成后应保存源图、裁切/导入元数据和用途说明，材质确实引用才能称为接入；概念图不能作为实机截图。颜色故障须先排查材质参数/加载/生成与Shader编译，不能用更多灯掩盖统一黑材质。

## 编码与验收顺序

1. 先修材质色彩与明确回退，不依赖未知天空捕获；以三角色和三种地板做引擎内颜色检查。
2. 落共享布局数据，生成新真实碰撞与同位置可见地板，移除旧整块矩形底板；运行边界/投影/非法坐标纯规则测试。
3. 适配出生点、AI路由、镜头，先完成码头一条可往返路线，再复制机制到另外两章。
4. 接入不同遭遇锚点与明确的Intermission推进方式，不做强制关门；保留NPC前后对话。之后放置地标、贴图和低成本装饰。
5. UE实机验证：三真人/单人带AI穿过窄桥、进出侧庭、救援、Boss预警、空中连招、重开、掉线恢复；记录截图、视频与帧时间。

本轮必须完成的是非矩形可走地板/实体外边界、窄宽和纵深差异、两个遭遇锚点、共享AI投影与镜头范围适配；低台限制30cm。强制推进门、复杂空间触发、80cm以上高台、多层寻路、传送带/落水/护送机制均为后续。

当前文档完成仅代表规划可供编码评审。没有UE编译、渲染、真实移动、AI寻路或三机联机验收证据，不能将坐标表或纯规则检查升级为地图验收完成。

## 本轮编码交付记录

规划评审后已接入 `LevelLayoutRules`、`AlphaRouteGeometry`、三章地标与Atlas、角色衣料、AI/敌人/Boss路线及镜头。开始本章战斗后先显示前进目标；存活真人距目标≤420cm、全队（含倒地）距目标≤1100cm，经过短暂停顿后由服务端激活遭遇。不会让AI独自替真人触发，不强制把倒地队友传走。

本轮只启用30cm可直接跨上的货台；没有高平台、移动平台或高差跳跃谜题。边界有低栏提示与阻挡，不包含坠水玩法。路线示意图： [level-layout-plan.svg](Images/level-layout-plan.svg)，来自共享C++布局数据，不是游戏截图。

当前8450项共享规则及UBSan通过，38项UE测试仅有源码；实际碰撞、角色移动、AI、材质与三机联机未运行。纯规则通过不代表本文件地图已实机验收。
