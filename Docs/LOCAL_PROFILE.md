# 本地档案、设置与章节重玩

## 使用方式

Tab菜单的“声音与镜头”包含战斗音量和镜头震动滑条。拖动不会写盘，点击“应用并保存到本机”后才保存并实时应用；0关闭对应反馈。未应用就关闭菜单会丢弃滑条改动。旧的AlphaAudioVolume和CameraShakeStrength控制台命令仍只改变本次会话，不更新保存值。

“章节重玩”中可选择已解锁的三章，或点击“继续旅程”进入上次记录的章节开头。仅房主/单人可带全队切章，准备/胜利/失败可用，战斗与前进集结阶段不可用。重玩从Arrival重新接NPC任务，恢复全队、清理遭遇与旧对话；同章重开也重置镜头取景。

完成战后NPC对话才解锁下一章，单纯刷怪结束不解锁。服务器通过可靠的玩家控制器通知当前队员保存完成记录；切章通知沿同一控制器可靠顺序发送，避免短暂Complete状态被下一章复制覆盖。客户端只能修改本机设置，不能把房主切到自己的存档章节。

首次使用从码头开始；更新前未被存档系统记录的旧进度无法推断。通关后的默认“继续旅程”指向下一已解锁章，最后一章保持第三章。已接受的角色选择也会保存，下一次准备阶段尝试恢复；玩家手动选角优先于延迟的默认恢复。

## 保存范围

使用UE SaveGame，本地slot为AlphaGameLocalProfile、UserIndex=0，通常位于平台的Saved/SaveGames目录。该目录不入Git。v1仅保存：

- 最高解锁章节、继续/重玩章节。
- 偏好角色。
- 战斗音量、镜头震动强度。

没有保存敌人、生命、能量、战斗波次、位置、物品或局域网连接；“继续旅程”不是中途战斗存档、断线重连或跨设备云存档。

## 兼容与错误

只接受当前原生SaveGame类、schema1，以及有限且合法的字段。缺slot尝试创建默认档；坏档、未知类、未来版本或非法字段使用内存默认值并进入只读，保留原文件，不静默迁移或覆盖。菜单独立显示档案错误，不覆盖局域网连接错误。

保存失败不提交内存中的候选设置；UI保持未保存状态，用户可修复磁盘空间/权限后重试。SaveGameToSlot不提供本项目额外的原子写入/跨进程文件锁承诺。写前复核现有版本，并合并较新的解锁数，避免同进程PIE实例的普通设置写回降低解锁。

没有UI自动删档或自动重置。ResetLocalProfile仅为显式原生维护接口，正常启动/错误恢复不会调用它。

## 验证

新增182项共享规则及UBSan检查，覆盖默认值、版本/字段拒绝、非法数值、解锁单调性与幂等、房主/安全阶段重玩门槛、极端整数。八套共9007项严格C++17检查及各自UBSan通过。

新增UE测试源码使用SaveGameToMemory/LoadGameFromMemory检查字段往返、未来版本与非法字段；不初始化真实档案GI，不访问真实slot。当前46项UE用例尚未执行。

本轮没有UE环境，尚未执行实际磁盘读写、写失败注入、菜单滑条、应用后重启、可靠RPC时序和多人重玩验收。用户反馈“测试通过”针对上一阶段，未附用例/构建/设备日志，不用来替代本轮验证。

## 实机检查

1. 启动后设置音量25%、震动0，应用，关闭游戏重开，确认滑条和实际反馈恢复。
2. 选择阿绫或闻灯，重启进入准备，确认恢复；立即手动换角不能被旧偏好覆盖。
3. 完成码头战后NPC对话，确认工坊解锁；退出后“继续旅程”从工坊入口接任务。
4. 已解锁章节可以在准备/结算重玩，未解锁和战斗中不可切换；局域网客户端也不能替房主切章。
5. 同章重开后没有旧对话确认、残留敌人或错误镜头位置；阵亡重开不清除已保存解锁。
6. 使用单独测试用户目录验证坏档/未来版及写失败，不修改日常进度；应有错误提示并保留原不兼容文件。
