# 《烬潮：归炉》工坊视觉规范

## 目标与证据边界

本轮目标是把基础方块原型推进为有东方工业奇幻特征、能辨认职业与招式的程序化视觉原型。优先保证三人侧视战斗清楚，再增加装饰。

程序化形体、构件拼装与材质脚本是开发资产，不是正式手工角色、骨骼动画或最终场景。当前没有 Unreal 实际渲染结果；概念描述、代码和离线检查不能作为游戏截图或画面达标证据。新增材质由 UE 编辑器 Python 管线生成，需要在目标引擎执行、编译并保存后才能作为已生成资源验收。

## 调色板与材质层次

下列 Hex 是 **sRGB 视觉参考**；C++ 建议经 `FLinearColor::FromSRGBColor` 转为线性颜色，避免把 Hex 通道直接当线性值造成过亮。以下百分比是画面面积指导，不是已测统计。

| 用途 | sRGB Hex | 材质表现 | 使用约束 |
|---|---|---|---|
| 黑铁主体 | `#20272C` | 偏冷，粗糙度 0.55～0.8，金属感局部出现 | 主体约 50%；避免大面积纯黑失去轮廓 |
| 青瓷构件 | `#4B7774` | 柔和青绿，粗糙度 0.25～0.45 | 中景识别点，不能冒充友方技能边界 |
| 黄铜边缘 | `#A87C45` | 暖色金属，粗糙度 0.3～0.55 | 接缝、铆钉、机械转折，避免通体金色 |
| 炉火核心 | `#FF722B` | 小面积暖色发光 | 明亮核心面积受限，不能压过敌方预警 |
| 灰白烟尘 | `#B9B4A5` | 低对比气氛 | 主战斗平面减少遮挡 |
| 深背景 | `#111B24` | 冷、低细节 | 与主角边缘形成明度差 |
| 沈砚强调 | `#B54A42` | 暗朱红布与黄铜 | 宽肩、长刀轮廓优先 |
| 阿绫强调 | `#45BDA7` | 青绿织物与机关光 | 短衣、双刃与侧置机关 |
| 闻灯强调 | `#E1BD67` | 灯黄与深蓝长衣 | 灯杖、竖直轮廓与圆环 |
| 敌方预警 | `#F05B38` → `#FFD24A` | 接近生效时从橙红转黄 | 同时展示范围、方向和进度，不只靠颜色 |
| 友方合作 | `#77BDE8` | 低面积冷光与连接弧 | 与敌方危险的封闭边界形状区分 |

材质分为主表面与效果表面：主表面使用实体不透明材质，控制金属度/粗糙度；效果表面按需要使用发光，但不假定设置 `Glow` 就会发光。参数名必须与实际 master 图连接一致。透明度需要正确的 Blend Mode 与 Opacity 接线，不能依赖 BaseColor 的 Alpha 自动透明。

## 角色形体与动作语言

所有角色的脚底必须与胶囊底面、地面阴影一致。视觉构件默认无碰撞、不参与导航，不改变原有攻击与移动胶囊。

| 对象 | 形体语言 | 动作表现 | 三人可读性 |
|---|---|---|---|
| 沈砚 | 肩宽、重胸甲、短披挂、明显长刀 | 稳定支点、肩胯带动、重斩随动 | 不用巨大持续光圈掩盖刀势 |
| 阿绫 | 窄躯干、侧置机关、短双刃、偏轻的腿部比例 | 前倾、轻快摆动、短促爆发 | 高频攻击分段可读，光迹短命 |
| 闻灯 | 竖长衣摆、长杖、灯环与灯笼 | 圆弧与稳定悬停节奏 | 控制范围边界明确，中央尽量留空 |
| 普通敌人 | 低头、块状护甲、断裂或偏斜构件 | 预备姿势夸张、受击方向清楚 | 不与玩家共用全部轮廓和服装强调色 |
| 铸炉官 | 更宽的上体、机械锤、炉核与左右非对称结构 | 落锤前蓄势、阶段变化有形体提示 | 大体型不覆盖所有预警，脚底落点清楚 |

程序化摆动只能作为临时表现，不能宣称已有手工动画或动作捕捉。攻击有效时间仍由战斗系统决定，视觉不能生成第二套伤害判定。

## 场景构图与灯光

- 前景：低矮栏杆、短管道、少量框架；不遮挡脚底与地面危险区。
- 战斗平面：低细节、连续清楚的地面，维持既有宽度和碰撞。
- 中景：青瓷炉箱、黑铁梁柱、黄铜接缝、重复工坊模块。
- 远景：巨炉、管线与城市剪影，降低对比和饱和度。
- 镜头保持侧面斜视，让纵深可读；角色头部和跳跃顶部不能超出安全构图。
- 暖色主光建立炉火方向，冷色补光分离角色轮廓。少量局部灯服务重点，避免每个构件都放动态阴影灯。
- 曝光采用固定或窄范围控制作为原型基准，记录所用曝光方式与目标值。不能用极强发光补偿未确认的曝光问题。
- Bloom 只强化少量能量核心，关闭/降低 Bloom 后仍须看见关键预警边界。

## 招式与特效图形语言

普通轻击使用短弧和一次接触闪光；重击使用较宽但短暂的弧线与冲击环。角色技能沿武器、位移和控制区域表达用途。合作反馈采用短连接弧或上升碎片，避免覆盖整个目标。

敌方预警使用连续边界与向内/向前的进度线：扇区显示两条侧边与弧，直线显示完整矩形，落锤显示圆环。预警必须在高低画质、不同曝光与背景上可辨认，不能仅依赖透明叠色。死亡、打断、重开、Actor 销毁时应清理预警和临时效果。

形体特效也需要实际寿命上限、实例数量上限与清理策略。局部脉冲随时间衰减，不能在服务器重复触发或复制每个装饰组件。

## 初始性能预算与视觉验收

以下是原型预算，需指定 Windows 目标硬件后测量和调整，不是当前性能结果：

| 项目 | 初始预算 |
|---|---|
| 三人战斗目标 | 1080p，60 FPS；CPU/GPU 帧时间分别记录 |
| 单角色程序化静态构件 | 尽量不超过 24 个可见构件；重复材质合批 |
| 单个瞬时攻击效果 | 优先 1 个批量组件、1～2 个材质槽；避免逐片 Actor |
| 同时临时视觉对象 | 设置硬上限；压力测试至少覆盖三人同时技能与 Boss 预警 |
| Boss 预警 | 保持批量实例，静态拓扑尽量不每帧重建 |
| 动态阴影光 | 战斗区初始不超过 2 个主要贡献者，其余局部灯关闭阴影 |
| 透明层 | 角色与地面危险区避免多层覆盖；能不透明实现的边界优先不透明 |

正式验收需保存真正的 UE 实机截图/录像，并记录构建、画质、分辨率和设备。分别检查静止、三人普通攻击、三人技能、Boss 大招、救援及死亡重开。确认伤害范围与画面一致、角色不浮地、装饰不挡移动、关键效果未因 cook 丢失、对象数量在长时间战斗后回落。
