# 《烬潮：归炉》项目执行计划

## 目标与当前阶段

目标是 Windows 平台、1～3 人局域网合作的 2.5D 动作闯关游戏。镜头采用侧面斜视，角色在有限纵深的三维战场移动。完整产品优先投入动作打击感、角色辨识度和画面表现。

当前阶段是 **M0 运行验收阻塞，M1 源码推进中**。当前已进入 UE5.6 工程、灰盒战场、基础动作、三职业能力、救援、共鸣、三波敌人与 Boss 战的集成。功能清单和证据见 `M1_PROGRESS.md`。代码集成、编译通过、实机可玩是不同状态；只有取得对应证据后才更新验收状态。当前云环境没有 Unreal Editor，不能据此声明 UE 编译或 Windows 联机测试通过。

## 开发角色与边界

| 角色 | 负责人 | 当前任务 | 文件责任范围 |
|---|---|---|---|
| 项目经理、架构与集成、质量负责人 | 主智能体 | 工程结构、配置、房间面板、HUD、整合评审、检查与交付 | 工程根目录、配置、UI、控制器与公共集成文件 |
| 战斗程序 | combat 子智能体 | 权威伤害、生命与架势、轻重攻击、冷却、同队过滤 | `Source/AlphaGame/Combat/` |
| 角色与 AI 程序 | characters 子智能体 | 移动、闪避、三职业外观、敌人追踪、倒地救援 | `Characters/`（不含 Boss）、`Coop/` |
| 联机、关卡与 Boss 程序 | gameplay 子智能体 | 人数限制、生成场景、波次、Boss、连接错误处理 | `World/`（控制器由主智能体集成）、`Characters/Boss/` |
| 能力程序 | abilities 子智能体 | 三职业U/I/O、能量、合作架势反馈 | `Source/AlphaGame/Abilities/` |
| 制作、设计与独立 QA | production 子智能体 | 设计基线、任务分解、纯规则边界测试、交叉审查 | `Docs/`、规则测试脚本 |
| 集成审查 | integration_review 子智能体 | 只读检查引擎接口、网络与界面行为 | 整个工程，只读 |

共享接口变更先通知相关负责人。各负责人不覆盖其他人的文件；主智能体负责最终集成。灰盒代码可以使用引擎自带基础形体，避免等待模型、动画和材质制作。

## 范围控制

当前为功能与程序化美术原型源码。正式手工角色模型、完整动作树与骨骼顿帧、局域网自动发现、正式关卡及配音/成品音效仍待开发。三角色技能、救援、共鸣与 Boss 已进入代码，不等同于完成完整设计或通过运行验收。Boss 预警已使用可保留于 Shipping 的实体实例网格，仍缺打包视觉验证；技能反馈已改为可打包网格；完整主材质需要先在 UE 编辑器运行生成脚本。

首发暂不包含开放世界、联网匹配、房主迁移、装备词条系统和分屏。按用户新增需求，已实现测试用 AI 队友补位；正式复杂导航、队友剧情和战术系统仍不在本轮范围。采购资产前核验许可证和团队使用范围。先确认三人战斗可读性，再扩充特效与场景细节。

每个任务完成需提供：修改文件、行为变化、验证证据、已知限制和后续任务。Windows 测试应按 `ACCEPTANCE.md` 留存结果。

最新用户操作规则优先：WASD全向、双击奔跑、J五段/空中、K跳跃、L面向翻滚、U/I/O能量。当前已在源码整合，下调敌人基准，后续以 `PLAYER_CONTROLS.md` 验收；正式骨骼动画与手感仍需实机迭代。
